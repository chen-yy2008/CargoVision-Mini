# CargoVision K230 v1 阶段状态

更新时间：2026-11-19

## 1. 归档范围与仓库边界

本仓库主体是 Windows + Python + OpenCV 桌面视觉项目。K230 v1 板端程序目前位于独立本地工作区 `CargoVision_K230`，尚未纳入本仓库。本次 GitHub 更新只归档文档，不同步板端源码、测试脚本或 SD 卡内容。

本记录描述的是 K230 视觉端的阶段进度，不代表整机发布或比赛验收。

## 4. 当前诊断协议边界

第一版使用 LF 结尾的 ASCII 文本。请求示例：

```text
CAPTURE,J42,120.5,-5.0,DIAG
```

诊断结果示例：

```text
RESULT,J42,18,PX,1,1,red,120,87
```

- 请求包含任务 ID、STM32 上报的机械 X/Y（mm）和任务类型。
- `PX` 明确表示像素坐标；请求中的机械位置目前只作为上下文，不参与机械绝对坐标计算。
- 同一时间只处理一个请求。
- 当前版本没有 `MOVE` 电机动作路径，不会驱动机构。
- UART 默认关闭；本地实现尚未部署到 SD 卡正式启动环境，也未修改启动入口或 STM32 固件。

完整示例和接线说明见 [UART 诊断通信说明](K230_UART_DIAGNOSTIC.md)。

## 5. 坐标转换现状

- PC 端四点工具通过 TL、TR、BR、BL 四角和矩形实测宽高计算单应矩阵 `H`。
- K230 v1 的 `workplane.py` 可将有效区域内的像素质心投影为局部 `center_mm`。
- 局部原点为标定矩形 TL，局部 +X 沿 TL→TR，+Y 沿 TL→BL。
- 当前板端配置 `workplane_file=null`，尚无实际加载的工作平面标定；实时结果仍是像素坐标，`mm_status=uncalibrated`。
- 机械绝对坐标转换尚未实现。相机随龙门架移动时，需要结合参考位置、龙门架位移、局部轴到机械轴的方向变换，以及与曝光帧对应的机械位置。
- 现场标定前必须确认目标平面、机械原点、轴向、上报位置的参考点、相机安装姿态和工具中心偏移。

具体步骤见 [现场标定指南](K230_CALIBRATION_GUIDE.md)。

## 7. 下一次实验室建议顺序

1. 用杜邦线短接 K230 GPIO11（TX2）与 GPIO12（RX2），运行 `tools/uart2_loopback.py`；接线前断电，回环只连接 TX/RX，不接 3V3。
2. 达到预期结果后，再按协议与电控队友完成 K230—STM32 双向收发；确认两端逻辑电平兼容并共地。
3. 确认回零、机械坐标参考点、位置有效性和停稳锁存方式。
4. 固定相机安装姿态，采集参考标定帧，测量机械参数并生成实际 `raw` 平面标定。
5. 使用独立已知点，在多个龙门架位置及正反方向验证机械绝对坐标误差和重复性。
6. 坐标验收通过后，再讨论正式运动指令和电机联动。
